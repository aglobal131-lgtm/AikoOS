# AUTOMATION DATABASE

> Version: 1.0
> Module: Automation

---

# 1. Purpose

The Automation module stores all scheduled tasks, reminders, recurring jobs, and execution history.

It enables Aiko to perform actions without requiring an immediate user request.

---

# 2. Design Goals

The Automation database must:

* Persist scheduled work.
* Survive server restarts.
* Track execution history.
* Support retries.
* Support recurring schedules.
* Support cancellation.
* Support future distributed workers.

---

# 5. Schedules Table

## Purpose

Defines recurring or one-time schedules.

### Columns

| Column       | Type         | Description                  |
| ------------ | ------------ | ---------------------------- |
| Id           | UUID         | Primary key                  |
| UserId       | UUID         | Owner                        |
| Name         | VARCHAR(150) | Display name                 |
| ScheduleType | SMALLINT     | Once / Daily / Weekly / Cron |
| Expression   | TEXT         | Schedule expression          |
| TimeZone     | VARCHAR(100) | Time zone                    |
| IsEnabled    | BOOLEAN      | Active state                 |
| NextRunAt    | TIMESTAMP    | Next execution               |
| CreatedAt    | TIMESTAMP    | Creation time                |
| UpdatedAt    | TIMESTAMP    | Last update                  |

---

# 6. Tasks Table

## Purpose

Represents work generated by a schedule or created manually.

### Columns

| Column     | Type      |
| ---------- | --------- |
| Id         | UUID      |
| ScheduleId | UUID      |
| TaskType   | SMALLINT  |
| Payload    | JSONB     |
| Priority   | SMALLINT  |
| Status     | SMALLINT  |
| CreatedAt  | TIMESTAMP |

---

### Status Values

| Value | Meaning   |
| ----- | --------- |
| 0     | Pending   |
| 1     | Running   |
| 2     | Completed |
| 3     | Failed    |
| 4     | Cancelled |

---

# 7. TaskExecutions Table

## Purpose

Stores execution history.

### Columns

| Column     | Type      |
| ---------- | --------- |
| Id         | UUID      |
| TaskId     | UUID      |
| StartedAt  | TIMESTAMP |
| FinishedAt | TIMESTAMP |
| DurationMs | INTEGER   |
| Result     | JSONB     |
| Error      | TEXT      |

---

# 8. ReminderHistory Table

Stores reminders already delivered.

Purpose:

* Prevent duplicate notifications.
* Build reminder history.
* Future analytics.

---

# 10. Ownership Rules

Only the Automation module may:

* Create schedules.
* Generate tasks.
* Retry failed tasks.
* Mark completion.

Other modules request automation through service interfaces.

---

# 11. Performance

Recommended indexes:

* NextRunAt
* Status
* UserId
* ScheduleId

Workers should always fetch the earliest pending task first.

---

# 12. Edge Cases

The system must support:

* Missed schedules.
* Server downtime.
* Duplicate execution attempts.
* Clock drift.
* Time zone changes.
* Long-running tasks.

---

# 13. Future Expansion

Possible future features:

* Task dependencies.
* Workflow engine.
* Conditional schedules.
* Calendar integration.
* Distributed workers.
* Task priorities based on AI reasoning.

---

# 14. Summary

The Automation database provides durable scheduling and execution tracking, ensuring Aiko can reliably perform future actions even across restarts and infrastructure changes.
